# 🛡️ Cryptexora - Machine-Learning Intrusion Detection System

A beginner-friendly web app that uses a **K-Nearest Neighbors (KNN)** classifier from **scikit-learn**
to label network traffic as **Normal** or **Suspicious**. It is a rebuild of the earlier rule-based
Cryptexora project: the `if/else` rules were replaced by a model that *learns* from example data.

**Stack:** Python · Flask · scikit-learn · SQLite · HTML/CSS/JavaScript

> ⚠️ **Read this before presenting the project**
> * The model predicts from **traffic features** (duration, packet count, bytes, failed connections).
>   An **IP address alone is never proof** of malicious activity - the IP field is only a label stored in the history.
> * The app does **not monitor live network traffic** and captures no packets. You type values or use the demo presets.
> * The dataset is **synthetic** (generated by `generate_dataset.py`). Accuracy figures show that the pipeline works;
>   they are *not* a claim about real-world protection. A production IDS would train on real labelled data (e.g. CIC-IDS2017 / NSL-KDD).

## 3. Setup on Windows with VS Code

1. Install **Python 3.10 or newer** from python.org (tick **"Add Python to PATH"**) and **VS Code** with the *Python* extension.
2. Unzip the project and open the folder in VS Code (**File → Open Folder**). Open a terminal (**Terminal → New Terminal**).
3. Create and activate a virtual environment:

   ```powershell
   python -m venv venv
   venv\Scripts\activate
   ```
   *If PowerShell says scripts are disabled, run this once, then activate again:*
   `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`
   *(or use Command Prompt, or run `venv\Scripts\activate.bat`).*
   In VS Code choose the interpreter: **Ctrl+Shift+P → "Python: Select Interpreter" → `venv`**.
4. Install the libraries:

   ```powershell
   pip install -r requirements.txt
   ```
5. *(Optional but recommended - shows the ML training output)* train the model:

   ```powershell
   python generate_dataset.py
   python train_model.py
   ```
   Not required: the app trains the model automatically if the saved model is missing or was made by a different scikit-learn version.
6. Start the app:

   ```powershell
   python app.py
   ```
7. Open **http://127.0.0.1:5000** and sign in with **admin / admin123**.

The SQLite file `cryptexora.db` is created automatically on first start (or run `python database.py`).
To reset all history, delete `cryptexora.db`.

## 5. How the machine learning works (simple explanation)

**Features (inputs)** - 4 numbers per connection:

| Feature | Meaning | Typical clue |
|---|---|---|
| `duration` | seconds the connection lasted | floods are often very short |
| `packet_count` | packets sent | huge counts → flooding |
| `bytes_transferred` | total bytes | huge volume |
| `failed_connections` | failed attempts | many failures → port scan / password guessing |

**Label (output)** - `normal` (0) or `suspicious` (1).

**KNN idea** - "tell me who your neighbours are and I'll tell you who you are". For a new connection the model finds the
*k* most similar rows in the training data and takes a majority vote. If 4 of 5 neighbours are suspicious, the prediction is
suspicious with 80% confidence (severity HIGH when ≥ 80%, MEDIUM for 50-79%, LOW for normal).

**Pipeline** (`train_model.py`):
1. `log1p` transform - shrinks huge values so they don't dominate.
2. `StandardScaler` - puts all features on the same scale (KNN uses distances, so this matters).
3. `KNeighborsClassifier` - *k* is chosen from {3, 5, 7, 9, 11} using 5-fold cross-validation.
4. Evaluation on a held-out 20% test set: accuracy, precision, recall, F1, confusion matrix → `model/metrics.json`.
5. The whole pipeline is saved with `joblib` to `model/knn_model.joblib` and reused by the web app.

**Why 100% test accuracy appears:** the sample set is small (600 synthetic rows, 120 in the test split), so the test score can be
very high or even perfect. Cross-validation accuracy (≈ 97%) is a more honest number. Say this if asked - do not claim real-world accuracy.

**Explanation shown to the user:** the app compares each value to the 95th percentile of *normal* training traffic and lists the
features that exceed it, plus "X of the k most similar records were suspicious".

## 6. Testing

Automated (uses a temporary database, never your real data):

```powershell
python -m unittest discover -s tests -v
```

Covers: the model is a real `KNeighborsClassifier`, presets classify correctly, IP is not a feature, login/logout,
hashed passwords, CSRF protection, input validation, history save/filter/export/clear, dashboard counts.

Manual checks: wrong password is rejected · `/dashboard` redirects to login when signed out · invalid IP `999.1.1.1` and
negative numbers show an error · the same IP gives different results for different features.

## 7. Security notes

* Passwords are hashed (PBKDF2-SHA256 via Werkzeug); only the hash is stored.
* All SQL uses `?` placeholders (prevents SQL injection); Jinja auto-escapes output (prevents XSS).
* Every POST requires a CSRF token. Inputs are validated (IP format, numeric ranges).
* **Demo credentials are for local use only.** Before deploying, set `ADMIN_PASSWORD` (before the first start, or delete `cryptexora.db`) and `SECRET_KEY`.
* Not included to keep things simple: login rate-limiting, password change page, multiple user roles, HTTPS (use your host's).

## 8. Deployment (example: Render.com, free tier)

1. Put the project in a GitHub repository (the `.gitignore` already excludes `venv` and the database).
2. On Render: **New → Web Service** → connect the repo.
3. Settings:
   * **Build command:** `pip install -r requirements.txt && python train_model.py`
   * **Start command:** `gunicorn app:app`
   * **Environment variables:** `SECRET_KEY` = a long random string, `ADMIN_PASSWORD` = your own password
4. Deploy and open the URL.

Notes: free hosts have **ephemeral disks**, so SQLite history can reset on redeploy/restart (use a persistent disk or a hosted database for real use).
`gunicorn` runs on Linux; on a Windows server use `waitress` (`pip install waitress`, then `waitress-serve --port=8000 app:app`).
Never run with `debug=True` on a public server - set up through gunicorn as above, which ignores it.
